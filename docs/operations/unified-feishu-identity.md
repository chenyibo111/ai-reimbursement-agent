# 统一飞书身份链路运维手册

## 部署边界

迁移环境通过同一公网入口发布 React 工作台、`/api/auth/` 和 `/api/v1/`。`/internal/` 必须由边缘代理直接返回 404；Go 员工投影接口只允许同一容器网络内的 Auth BFF 与飞书 Worker 调用。Go API 只使用 Docker `expose`，不得映射宿主机端口。

在多员工演练前，必须准备固定 HTTPS 域名，并把该域名同时写入 `APP_PUBLIC_URL` 与飞书 OAuth 回调配置。临时 `trycloudflare` 地址不能用于该环境。

## 配置与启动

分别生成并以部署平台 Secret 注入以下随机值：会话 Cookie 密钥、报销 JWT 签名密钥、员工投影密钥、Agent 服务密钥。它们不得相同，也不能出现在 URL、Git、Docker 镜像、反向代理文件或日志中。

用飞书 `open_id` 白名单配置管理员和财务复核员；两个名单不能包含同一账号。启动前确认 Auth BFF、飞书 Worker 与 Go API 均能读取 JWT 签名密钥；只有 Auth BFF 与 Worker 能读取员工投影密钥。

启动顺序：

1. 执行 Go 数据库迁移，并启动 PostgreSQL、MinIO、OCR、ClamAV、NATS。
2. 启动迁移 Profile 的 Go API、Go Worker、React 静态站点和边缘代理。
3. 启动 Auth BFF 与飞书机器人 Worker。
4. 仅通过边缘代理地址访问工作台；不直接暴露 Go API 或内部员工同步路径。

## 验收

1. 使用飞书 OAuth 登录，刷新 React 页面后确认 Cookie 能重新获得短期 Token，浏览器持久化存储和地址栏没有 Token。
2. 用普通员工执行创建、上传和提交；确认过期 Token 只刷新并重试一次，写请求保留同一幂等键。
3. 首次向飞书机器人发送“开始报销”；确认创建员工投影、私有会话和草稿。投影不可用时机器人只回复通用重试提示。
4. 用管理员和财务复核员分别检查权限；再尝试公网访问内部路径，必须得到 404。

## JWT 密钥轮换与回滚

HS256 当前不支持双密钥验签。轮换时在维护窗口内同时更新 Auth BFF、飞书 Worker 和 Go API 的 JWT 签名密钥，并一起重启；已签发的短期 Token 最多在 15 分钟内失效，客户端会重新经 Cookie 换取 Token。若发现认证错误持续增加，恢复上一份完整 Secret 集合并重启这三个服务；不要删除员工投影、报销单或消息队列。

若切流失败，先从边缘入口撤回对应员工/渠道的流量，并保留 Go 已创建数据和审计记录。不得反向同步、清库或把私网接口临时暴露到公网。
