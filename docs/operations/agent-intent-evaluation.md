# Agent 意图评测数据维护

`tests/fixtures/intent-eval/dev-v3.jsonl` 用于开发与调优；`holdout-v3.jsonl` 是锁定的回归保留集。旧版 `dev.jsonl` 和 `holdout.jsonl` 保留以便对比，不能将旧分数当成当前完整能力的成绩。

1. 从本人已授权的自测会话或经同意的员工反馈中记录原始问法与必要的前两轮上下文。不要直接导出完整聊天记录。
2. 删除姓名、飞书 ID、真实单号、发票号、手机号、金额等可识别信息，替换成虚构的 `BX20261024-0004` 等样例。只保留判断意图所必需的内容。
3. 人工标注 `expectedAction`；对搜索、选单、删除、提交准备等动作，同时标注 `expectedDecision` 中的目标单号、序号或筛选条件。把否定提交、目标不清和跨渠道指代标为相应 `riskTags`。
4. 新收集的样本先加入开发集，标记 `provenance: "self_test"`。新一轮独立样本应另建版本化保留集，先锁定再调优；不要因模型失分而修改现有保留集答案。
5. 用 `npm run eval:intent -- dev-v3` 诊断，再对完整 `holdout-v3` 运行 `npm run eval:intent -- holdout-v3`。这会请求真实模型，可能计费；单条抽样只检查连通性。输出仅含样本 ID 和指标，不含原句。

动作宏 F1 与参数准确率分开看。若动作正确但单号或搜索条件错误，参数准确率会下降。对已标注的单号、单据序号和票据序号，任何目标错误都会计入 `targetReferenceErrors`，完整保留集门槛要求为 0；这也覆盖查询与进度等只读动作。危险写入目标错误或否定提交被判为提交准备，同样会使门槛失败。最终 `确认提交` 是服务端精确文本和 Go 校验流程，不由意图分类器评分，应单独验收。
