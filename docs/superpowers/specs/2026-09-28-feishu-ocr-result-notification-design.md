# 飞书 OCR 异步结果通知设计

## 目标

员工在飞书会话上传票据后，系统应立即确认已接收；票据识别异步结束后，机器人必须在原会话主动发送可理解的识别结果或待补充项。该通知不能依赖浏览器保持打开，也不能因机器人短暂重启而永久丢失。

## 范围

本设计只覆盖从**飞书会话上传**产生的 `RECEIPT_EXTRACTION` 任务。Web 工作台上传保持现有行为：在页面中查看识别结果，不生成飞书消息。

不在本次范围内：人工复核员完成修正后的二次通知、政策同步通知、富文本卡片，以及重做 OCR 模型本身。

## 当前问题

飞书机器人 Worker 同步完成附件接收、创建草稿、上传附件并入队 OCR 后，只回复“票据已上传并进入识别流程”。`job-worker` 随后完成 OCR 或创建复核任务，但没有保存飞书会话投递目标，也没有调用飞书消息 API。因此识别字段、低置信度和人工复核状态无法返回给员工。

## 方案：持久化通知 Outbox

新增一个由数据库维护的 OCR 结果通知记录。它在飞书上传路径创建，关联 OCR 任务、票据、会话及飞书 `chat_id`；机器人 Worker 轮询并投递，不让 `job-worker` 直接依赖飞书 SDK。

```text
飞书附件事件
  -> 上传票据并创建 OCR 任务
  -> 创建 PENDING 通知记录（仅 FEISHU 渠道）
  -> 立即回复“正在识别”

job-worker
  -> 完成 OCR 任务 / 标记 REVIEW_REQUIRED / 最终失败

feishu-bot-worker
  -> 领取终态且未通知的记录
  -> 读取票据识别字段和任务状态
  -> 发送一条新的 chat 消息
  -> 成功后标记 SENT；失败后按有限重试策略处理
```

## 数据模型

新增 `ReceiptExtractionNotification`：

- `id`：主键。
- `jobId`：唯一关联的 `AsyncJob`，保证每个 OCR 任务最多产生一个员工通知。
- `receiptId`、`claimId`、`conversationId`：供生成消息与写入会话历史。
- `channel`：本期固定为 `FEISHU`。
- `chatId`：投递目标；不保存飞书访问令牌或附件原文。
- `status`：`PENDING`、`PROCESSING`、`RETRY_WAIT`、`SENT`、`CLOSED`。
- `attemptCount`、`availableAt`、`leaseUntil`、`failureCode`、`sentAt`：领取、重试与诊断信息。
- `createdAt`、`updatedAt`。

对 `jobId` 加唯一约束，对 `status + availableAt` 加索引。Worker 使用条件更新领取记录；过期租约回收为可重试状态。发送时使用通知 ID 作为飞书消息幂等键，避免“发送成功但标记前崩溃”导致可见重复消息。

## 写入与投递边界

`uploadReceipt` 继续负责上传附件并创建 OCR 任务，但返回任务 ID。飞书会话的附件处理在拿到任务 ID 后创建通知记录；Web 调用方不传通知上下文，因此不会创建记录。

机器人 Worker 持有飞书客户端，新增“发送到 chat”的能力。通知发送成功后，Worker 将同一段文本追加为 `ASSISTANT/FEISHU` 会话历史，记录 `jobId` 和 `receiptId`，确保员工后续对话具备该上下文。

若通知创建或会话消息持久化失败，不能回滚已上传票据或 OCR 任务；记录失败日志并保留员工的工作台路径。若飞书发送失败，使用有限重试，耗尽后状态为 `CLOSED`，不触发 OCR 重跑或人工复核。

## 消息内容规则

以 `invoiceNumber`、`issuedOn`、`totalAmountCents` 为关键字段：

1. 三项都有值且置信度均不低于 `0.9`：回复“识别完成”，列出发票号码、开票日期、价税合计。
2. 任一项为空或置信度低于 `0.9`：回复“识别结果需要确认”，仅展示有值字段，并逐项列出待确认/补充字段。
3. 任务为 `REVIEW_REQUIRED`：在上述信息后追加“已转人工复核”；不把低置信度识别值表示为确定结果。
4. OCR 任务最终关闭或识别载荷不存在：回复“识别未完成”，提示在工作台补充或重新上传。

每条通知附带报销工作台链接。内容为确定性模板，不调用大模型，避免延迟、幻觉与额外成本。

## 安全与可靠性

- 只为已绑定飞书账号、经现有会话认证处理的飞书附件创建通知。
- 通知文本不得含对象存储 key、飞书访问令牌、OCR 原始全文或管理员复核内部信息。
- `chatId` 仅用于发送到原会话；不允许来自浏览器请求写入。
- 任务完成是通知发送的前提；通知状态不会修改报销单、票据识别结果或人工复核决定。
- 已发送通知永久保留状态用于排查；本期不做自动清理策略。

## 验收标准

1. 飞书上传票据后，员工立即收到“正在识别”；OCR 成功后收到第二条摘要消息。
2. 对缺字段或低置信度票据，第二条消息明确列出待确认字段；创建的 OCR 复核任务与消息状态一致。
3. 从 Web 上传票据不产生 `ReceiptExtractionNotification`，也不发送飞书消息。
4. 机器人 Worker 重启、通知暂时发送失败时，待发送记录可恢复并重试；同一通知不产生重复可见消息。
5. 所有通知消息都包含对应报销工作台链接，并追加至正确的飞书会话历史。
