# 草稿与票据删除设计

## 1. 目标与范围

员工可以在 AI 报销 Web 中删除自己尚未提交的报销草稿，或从草稿中删除一张已上传票据。删除必须同时清理私有 MinIO 原文件与对应业务数据，且不能让用户删除已提交报销单或他人的数据。

### 成功标准

- 仅 `DRAFT` 草稿允许删除；已提交草稿没有删除入口，服务端也拒绝删除请求。
- 删除草稿会清理其全部 MinIO 附件及数据库关联记录；删除票据会清理该附件、关联费用明细和关联 AI 建议。
- 删除前有应用内二次确认，删除过程可感知，失败时保留可重试的页面上下文。
- 每个删除请求均校验登录员工、草稿状态和 `expectedVersion`，避免删除他人或覆盖刚被更新的草稿。
- 删除票据后，剩余票据的重复校验重新计算，不遗留已删除票据造成的阻断项。

### 不包含

- 已提交报销单的撤销、作废、归档或财务审核流程。
- 批量删除、回收站、定时清理和管理员代删。
- 恢复已删除的草稿或附件。

## 2. 生命周期与授权

| 操作 | 可用条件 | 服务端拒绝条件 |
|---|---|---|
| 删除草稿 | 当前员工拥有草稿，状态为 `DRAFT`，版本与 `expectedVersion` 一致 | 未登录、非本人、非草稿、版本冲突、草稿不存在 |
| 删除票据 | 当前员工拥有所属草稿，草稿为 `DRAFT`，票据属于该草稿，版本一致 | 未登录、非本人、票据不属于草稿、非草稿、版本冲突、票据不存在 |

浏览器只提交 `{ expectedVersion }`。服务端重新读取草稿、票据、对象键和关联数据；不得信任浏览器提交的附件 ID、对象键、费用明细 ID、字段值或文件名。

## 3. 删除一致性与恢复

MinIO/S3 与 PostgreSQL 不能组成一个跨系统事务，采用“授权预检 → 删除对象 → 数据库事务”的顺序：

1. 服务端读取草稿及对象键，校验员工、状态和版本。
2. 调用对象存储的幂等 `delete`。对象存储删除失败时，数据库保持不变并返回可重试错误。
3. 对象删除成功后，在数据库事务内再次以员工、`DRAFT` 状态和版本条件检查并删除数据。
4. 若数据库条件不再匹配，返回 `409`；再次发起删除安全地重试已不存在的对象删除。

草稿删除依赖现有外键级联删除 `Receipt`、`ExpenseItem`、`AgentFieldProposal`、`ValidationResult` 与普通草稿审计事件。因为这些审计事件会随草稿级联删除，新增独立的 `DeletionAuditEvent` 保存最小删除事实：员工 ID、被删草稿 ID、操作类型、票据数量与时间；不保存对象键、附件原文、发票字段或密钥。

票据删除在同一数据库事务内删除：该票据关联的 Agent 建议、费用明细、票据行，并写入 `RECEIPT_DELETED` 草稿审计事件。删除后重新生成当前草稿仍存在票据的重复文件/重复发票校验结果；不能继续保留由已删除票据产生的阻断项。

## 4. API 契约

```text
DELETE /api/claims/:claimId
body: { expectedVersion: number }
response: 204 No Content

DELETE /api/claims/:claimId/receipts/:receiptId
body: { expectedVersion: number }
response: { receiptId: string, version: number }
```

错误响应沿用现有 `{ error: string }` 风格：`401` 未登录、`403` 非本人、`404` 不存在、`409` 非草稿或版本冲突、`502`/`500` 对象存储或服务端暂时失败。客户端展示中文、可恢复的操作提示，不显示对象键、存储地址或底层异常。

## 5. 前端交互

新增共享的应用内危险操作确认弹窗，使用 `role="alertdialog"`、焦点进入、焦点约束、Escape 关闭与焦点恢复；不使用 `window.confirm`。

- “我的报销单”列表仅在草稿行显示“删除草稿”次要危险操作；确认成功后留在列表，并移除该行。
- 工作台每张票据卡显示“删除附件”；确认内容包含稳定附件显示名并说明会移除该票据对应费用明细和 AI 建议。
- 确认按钮使用危险样式且在请求中显示“删除中…”。取消按钮默认获得焦点。
- 删除成功后以页面内 `role="status"` 提示并刷新服务端草稿/校验；失败时弹窗保持打开，显示重试说明。
- 已提交单据不显示这些操作；服务端拒绝仍以页面内错误说明反馈。

## 6. 数据与组件边界

- `ObjectStore` 新增 `delete({ key })`，S3 实现使用 `DeleteObjectCommand`。
- `deleteClaimDraft` 与 `deleteReceipt` 应用服务分别编排授权预检、对象存储删除、数据库事务和审计。
- Prisma 删除仓储封装版本条件、关联查询、事务删除和删除审计；路由只负责会话、严格 body 解析与 HTTP 映射。
- `DeletionAuditEvent` 是独立于草稿生命周期的删除留痕；普通 `AuditEvent` 继续记录仍存在草稿内的票据删除。
- `DestructiveConfirmationDialog` 是可复用确认组件；报销单列表和票据卡只提供业务文案与确认回调。

## 7. 验收与测试

1. 对象存储删除成功后，草稿删除移除草稿及其全部关系，并保留独立删除审计；对象删除失败时数据库不变。
2. 删除单张票据会移除其对象、费用明细和 AI 建议，递增草稿版本，并重新计算重复校验。
3. 伪造员工、跨草稿票据、提交态草稿、旧版本及额外 body 字段均被拒绝且不删除数据。
4. 浏览器验证草稿删除和票据删除的确认/取消、忙碌、成功、失败与键盘关闭行为；窄屏下操作不遮挡票据信息。
5. 现有上传、OCR、字段确认、Agent 建议、草稿校验与提交流程保持通过。
