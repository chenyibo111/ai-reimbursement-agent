# Agent 全链路离线评测设计

## 目标

把现有只评估模型动作分类的保留集扩展为可重复的会话评测：同一案例从用户消息进入生产 `runConversationTurn`，经过生产 Go 工具网关，检查动作、目标、工具调用、最终回复、引用和办理状态。输出仅含案例 ID、通过情况及安全失败类别。

## 边界

- 默认运行固定模型决策，供 CI 检验评测器和编排回归；显式真实模型模式调用当前配置的模型，用同一批案例检查语义判断。
- Go 后端、飞书和政策检索使用隔离的确定性替身；评测器调用真实会话编排和 `ReimbursementToolGateway`，但不写本机业务库、不上传真实票据、不声称测得真实 Go/飞书网络可靠性。
- 真实员工问题只在脱敏和人工标注后加入数据集，标明 `self_test` 或 `employee_anonymized`；合成样本标明 `synthetic`。现有四条 `self_test` 问法可复用，不把合成成绩称为员工准确率。
- 发布门槛先定义为安全错误零容忍：未经确认提交、错单写入或跨员工读取一旦出现，整次评测失败。普通动作与回答质量分别报告，不用一个总分遮盖危险错误。

## 案例与报告

每个 JSONL 案例可包含多轮、初始单据与票据、会话选中目标、政策证据。每轮声明期望动作、工具调用名称及目标、回复必须包含/不得包含的片段、引用数、最终单据/Intake 状态。解析时拒绝重复 ID、未知字段与未标注来源。

报告按案例与轮次返回结构化匹配结果、样本来源计数、动作/工具/回复/状态各自通过率和安全错误数；不输出原始消息、回复全文、政策正文、模型请求或密钥。抽样运行必须标记为 `sampled`，不可当作完整保留集结论。

## 验收

1. 固定模型全量通过，且故意错单调用、漏调用、虚构金额、提前提交、漏引用都能被评测器识别。
2. 真实模型运行使用生产相同提示词与解析器，失败按案例报告，不写业务数据库。
3. 数据集至少覆盖政策问答、本人金额、筛选/指代、补充字段、提交两步确认、群聊限制和越权拒绝；四条已脱敏自测问法纳入。
