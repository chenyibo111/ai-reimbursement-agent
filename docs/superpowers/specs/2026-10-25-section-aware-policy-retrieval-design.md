# 按章节检索报销政策设计

## 目的与现状

员工询问“住宿费报销具体规则”时，应得到北京/上海、广州/深圳/杭州等重点城市、其他城市三个档位以及相关例外，而不能因为文本切片而漏掉其中一个档位。政策问答仍只解释已授权、已同步的制度原文；报销校验和准入仍由已发布的结构化规则决定。

现有飞书客户端读取 `raw_content`，按行生成正文块，仅将 Markdown `#` 行识别为标题。实际飞书文档的“住宿费”在数据库里未形成标题路径。同步器以 `minLength: 80`、`maxLength: 1600` 调用分片器，正文一达到 80 字就刷新；当前活动快照中，600 元规则落在一片末尾，500/400 元规则落在下一片。问答只对最多五个向量近邻做阈值过滤，然后把每片前 500 字交给模型，没有邻片或完整章节补取。

## 目标、边界与不做的事

- 同一政策章节的相邻标准和例外规则在宽泛问题中可作为一个完整证据单元进入回答；具体问题仍能精确定位条款。
- 管理员在现有 `/admin/policy-sources` 来源行能看到最近活动快照的章节数、检索片数；来源行继续显示结构解析等安全失败原因。同步失败不替换上次成功快照，不新增管理页面。
- 旧来源在内容未变时也能按新索引版本重建；重建期间读请求继续使用完整的旧活动快照。
- Web 和飞书复用同一检索结果与引用；来源启用状态、快照原子切换和政策权限边界保持不变。
- 不引入独立向量库、重排模型或新的外部服务；不自动从制度文本发布可执行报销规则；不保证能回答文档未明确写出的情况。
- 不能把“多取几个相似片段”当作完整性保证，也不能静默截断长章节后声称已列出全部规则。

## 方案比较与选择

1. **只增大片段并补相邻片**：开发量小，但章节边界仍未知，可能把交通费或餐费带入住宿回答，且长章节依然可能缺项。
2. **短片段定位、章节展开作答（选定）**：结构化读取飞书文档，把标题下的有序正文作为章节存储；短片段用于向量定位，命中后按章节组装证据。为现有 PostgreSQL/pgvector 增加少量关系字段和检索逻辑。
3. **引入独立检索/重排平台**：可扩展复杂语料，但当前主要失败点是章节结构丢失，先增加基础设施不能解决这个根因。

## 导入与数据结构

飞书新版文档和 Wiki 仍由现有白名单来源及应用凭据读取。客户端优先使用飞书的“获取文档所有块”分页接口读取结构化块，保留文档顺序、标题级别、正文、列表项及可用的块标识；`raw_content` 只用于兼容或校验，不再作为有结构文档的唯一切片依据。官方接口说明见 [飞书文档块接口](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/list)。解析器对未知富文本类型记录安全错误；含有无法表达的重要政策正文时同步失败，不静默丢弃。

新增快照内的 `PolicySection`：章节序号、标题路径、正文、首个来源块定位和完整性标记。章节由真实标题层级决定；标题下的列表及表格条款按原序保留。标题缺失时，仅对格式明确且可验证的短篇纯文本结构使用保守回退；无法可靠判定边界的长文档同步失败并提示管理员，不伪造章节。

`PolicyChunk` 继续保存 1024 维向量，但关联 `sectionId`，记录片内顺序和匹配定位。按段落/完整列表项组成约 400–800 字的检索片，不拆断单条规则、表格行或标题与紧随其后的条款。向量输入包含标题路径及片内正文，持久化的原文片段仍只保存正文，以便宽泛主题问题也能命中简短的城市档位。每个真实标题下的正文先按标题路径索引；短章节可只有一个片，长章节可有多个片。检索时若命中城市档位等子标题，会沿标题路径找到问题对应的父主题，并把该父主题下的同级条款按原序拼成一个完整证据单元：`h1 住宿费 > h2 城市` 与 `h1 差旅费 > h2 住宿费 > h3 城市` 均覆盖全部档位；`h1 差旅费 > h2 交通费/住宿费` 仍能只展开住宿主题。标题与问题无法明确对齐时保守扩大到父主题，不仅取单个子标题。拼装后若超过模型证据预算，不做静默截断，而是标为证据不完整。

为快照增加显式 `indexVersion`（本次为 v2），并把唯一约束调整为来源、源版本和索引版本；“内容没变则跳过”的判断同时比较内容哈希和索引版本。这样旧来源无需改动飞书原文即可重新同步、生成新章节和向量。新索引完全写入后再切换活动快照；旧索引不被就地改写。

## 检索、回答与引用

1. 使用现有 Embedding Provider 对问题编码，在启用来源的活动快照中取候选短片（首版至多 12 个），保留既有相似度门槛作为初始值，通过回归集校准而非随意降低。
2. 以 `sectionId` 去重和排序，首版最多取三个相关命中，并依标题路径展开其父主题中的同级章节；同一个父主题只入模型证据一次。模型证据采用固定的 8,000 字符总预算（不含指令与问题）。先放最高排名的完整主题，再放后续完整主题；不能完整放入预算的主题不做静默截断，而是标记本轮证据不完整。属于同一住宿主题的三个城市档位必须一起进入回答上下文。
3. 将给模型的完整章节证据与给用户展示的短引用分开：模型得到章节标题、完整正文及来源；用户引用展示真正命中的具体条款、章节名和原文链接，不再对检索片机械地取前 500 字。
4. 当证据章节不完整、超预算或没有可靠结构时，不输出“完整规则如下”之类的结论；清楚说明只找到部分依据。未命中时沿用现有安全降级，不补造制度。
5. 模型仅基于返回证据作答；提示词明确要求宽泛规则问题枚举同章节中所有适用档位及例外，具体问题则回答相关档位。引用 ID 必须来自本次检索结果。文档内容仍按不可信输入处理，不得指挥工具或改变校验规则。

## 兼容、上线与验证

- 数据库迁移保留旧 `PolicyChunk` 与快照，旧活动快照在新同步成功前仍可读取；旧记录的 `sectionId` 可为空，检索代码有显式兼容路径，不假装旧数据已经按章节索引。
- 部署新代码和迁移后，管理员在现有 `/admin/policy-sources` 对已有政策来源执行一次重新同步；索引版本变化使内容相同的文档也会重建。当前同步 API 只返回异步任务已入队，不承诺同步完成；来源列表 API 从最近活动快照返回 `sectionCount` 与 `chunkCount`，现有来源行在任务完成并刷新后显示两者。解析失败使用现有来源行的失败状态。Embedding 或飞书接口失败时保持旧活动快照并显示失败原因。
- 已授权的既有制度在首次真实验收中包含一个嵌入电子表格块。当前只支持文档正文、列表及文档内表格，不读取电子表格单元格；为避免漏掉可能具有约束力的条款，遇到该块时同步明确失败为 `DOCUMENT_UNSUPPORTED_SHEET`，并保留旧快照。用户将其替换为普通文档表格后，2026-10-26 真实同步成功；若未来再次使用嵌入电子表格，仍须单独设计表格 API 读取、权限与完整性边界。
- 新增解析器、分片、版本升级、事务切换、章节展开与预算边界的单元/集成测试；针对现有住宿章节建立固定回归样本，检查宽泛问法同时包含 600/500/400 三档，定向问法只给出适用档位，且统一住宿及超标例外不被遗漏。
- 验收还覆盖跨章节污染（问住宿不混入交通费）、来源禁用、无命中、长章节部分依据提示，以及 Web/飞书引用一致性。通过自动测试后再用真实已授权文档同步并人工核对至少两轮问答。

## 交给实施者的选择

具体块类型映射、超长章节的保守阈值和检索排序权重可在实施时按飞书返回样本与回归测试确定；模型证据总预算首版固定为 8,000 字符，可通过测试验证后再调整。不得改变“真实章节优先、完整性可见、失败不替换活动快照”的约束。
