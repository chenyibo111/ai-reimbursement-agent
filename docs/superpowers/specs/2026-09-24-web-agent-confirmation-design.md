# Web 报销 Agent 与字段确认设计

## 1. 目标与范围

在现有 Web 报销工作台中，将固定回复的聊天演示升级为可配置的 OpenAI 兼容模型 Agent。Agent 帮助员工理解票据识别结果、识别下一项阻断信息，并提出字段修改建议；员工明确确认后才会写入草稿。

本阶段只覆盖 Web 端。飞书机器人后续只作为渠道适配层接入同一 Agent、草稿和工具网关。

### 成功标准

- 员工可在聊天框得到与当前草稿校验结果一致的澄清问题。
- Agent 可建议填写事由、金额、日期或发票号码，但不能自行写入。
- 员工确认建议后，字段通过既有版本保护与审计链路保存。
- 不可信的模型输出、附件文本或用户消息不能扩大工具权限。
- Agent 不能生成确认摘要或提交报销单。

### 不包含

- 飞书事件回调、消息幂等和飞书附件下载。
- 财务审核、审批、付款和 ERP/OA 对接。
- 模型自主判断票据真伪、报销合规性或自动提交。

## 2. 模型接入与数据边界

使用 OpenAI 兼容 Chat Completions 接口，服务端读取以下配置：

```dotenv
MODEL_PROVIDER="openai-compatible"
MODEL_BASE_URL="https://<provider>/v1"
MODEL_NAME="<model-name>"
MODEL_PROVIDER_API_KEY="<secret>"
```

模型适配器仅接收最小必要上下文：草稿事由、费用金额和来源、票据结构化字段与置信度、校验代码、当前员工消息。不得发送原始附件、对象存储地址、会话 Cookie、密钥或内部数据库标识。

配置不完整时，聊天接口返回可恢复的“AI 服务未配置”提示；开发环境可以保留显式 Fixture 模式，不能静默伪装为真实模型回复。

## 3. Agent 工具与权限

Agent 的模型输出必须满足 Zod 定义的结构化响应。工具名和参数由服务端白名单验证，任何不合法输出均不执行，并写入 `MODEL_RESPONSE_REJECTED` 审计事件。

| 能力 | Agent 行为 | 服务端约束 |
|---|---|---|
| 读取草稿 | 获取摘要与校验项 | 只允许当前员工所属草稿 |
| 提出字段建议 | 返回待确认的字段、值与理由 | 只允许 `purpose`、`invoiceNumber`、`issuedOn`、`totalAmountCents` |
| 确认写入 | 员工点击确认后调用字段服务 | 校验归属、草稿版本、字段类型、低置信度规则与审计 |
| 上传附件 | Web 聊天入口转交既有上传组件 | 重用文件安全、私有存储、OCR 与重复票校验 |
| 校验草稿 | 读取服务端规则结果 | Agent 无法修改或忽略结果 |

禁止 `request_submission`、`submit_claim`、删除附件、跨员工读取草稿及任意动态工具名。

## 4. 对话与确认流程

```text
员工消息或聊天附件
        ↓
Agent 读取草稿摘要与服务端校验项
        ↓
模型返回回复 + 0..n 个字段建议
        ↓
工作台显示建议卡片（字段、建议值、理由）
        ↓
员工确认 / 拒绝
   ↓确认                 ↓拒绝
字段更新接口              记录拒绝，不改草稿
   ↓
刷新草稿、校验面板和聊天记录
```

建议卡片只在当前草稿版本有效。员工确认时携带 `expectedVersion`；版本冲突后保留建议内容、刷新服务端状态，并要求员工重新确认。

聊天附件入口不得复制上传实现：它调用既有 `ReceiptUpload` 的上传与识别流程，完成后刷新聊天上下文、票据卡片、费用明细和提交前检查。

## 5. 数据与审计

新增持久化的 Agent 建议记录，关联 `ClaimDraft`，至少包含：建议字段、建议值、理由、草稿版本、状态（待确认/已确认/已拒绝/已过期）、创建与处理时间。该记录让刷新页面、未来飞书续办及审计都能恢复上下文。

员工确认的字段更新继续使用既有 `CLAIM_FIELD_UPDATED` 审计事件；额外记录 `AGENT_FIELD_PROPOSED`、`AGENT_FIELD_ACCEPTED`、`AGENT_FIELD_REJECTED` 和模型输出被拒绝事件。审计中不记录模型 API Key、原始附件内容或完整提示词。

## 6. API 与组件边界

- `ChatModel`：保留领域输入/输出，新增 OpenAI 兼容实现与受控工厂。
- Agent 编排用例：把模型建议转换为持久化建议，绝不直接调用字段写入。
- 建议确认接口：只接受建议 ID 与当前草稿版本；服务端读取建议，不信任浏览器传入字段和值。
- 建议拒绝接口：只改变建议状态并写审计。
- `ClaimChat`：显示模型回复、待确认建议卡片、确认/拒绝状态与聊天上传入口。
- 既有字段接口、`ReceiptUpload`、`ValidationPanel` 和 `SubmissionSummary` 保持为草稿事实与提交权限的唯一拥有者。

## 7. 错误与恢复

- 模型超时、网络错误或配置缺失：保留员工输入与既有建议，显示可重试的本地错误。
- 非法模型结构或未允许工具：不执行，记录审计，提示员工改用结构化表单。
- 建议过期或版本冲突：刷新草稿与校验项，建议标为过期；不得覆盖新值。
- OCR 或附件处理失败：沿用票据卡片中的失败状态和重新识别入口。
- 任意阻断项：提交前检查仍优先显示；Agent 不能降低其严重性。

## 8. 验收与测试

1. OpenAI 兼容适配器正确发送最小上下文，并拒绝缺失配置或无效响应。
2. Agent 对合法建议创建待确认记录；未知工具、越权字段和非法参数都不产生写入。
3. 员工确认建议后字段保存、版本递增、审计完整；拒绝建议不改草稿。
4. 版本冲突、重复票、低置信度与缺失金额仍以服务端校验为准，且 Agent 无法提交。
5. Web 浏览器覆盖建议显示、确认、拒绝、错误重试及聊天附件触发后的票据回显。
6. 现有创建草稿、上传、OCR、校验和最终提交回归保持通过。

## 9. 后续飞书适配

飞书阶段新增事件验签、消息幂等、员工身份映射和附件下载适配器。飞书只调用本设计的 Agent 用例与工具网关；复杂字段编辑、建议确认及最终提交统一跳转 Web，不在飞书内复制提交逻辑。
