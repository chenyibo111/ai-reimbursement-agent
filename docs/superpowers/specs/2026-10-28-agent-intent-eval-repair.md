# Agent 意图评测修复设计

## 目标

修复真实模型评测中删除票据的结构化输出与服务端契约不一致，并区分目标误指与安全澄清。保留 `holdout-v3` 原始样本和标注，用真实模型重新评测。

## 行为

- `DELETE_RECEIPT` 可附带模型提取的完整报销单号和票据序号；服务端只能在已选中本人草稿时处理。若模型单号与已选草稿不一致，不建立待确认操作，要求用户重新选择。
- 若员工本条消息明确写了不同单号，即使模型误返回已选草稿单号，也不建立待确认操作。
- 缺票据序号时，返回当前草稿的票据列表并要求指定；真正删除仍需独立的精确确认和版本校验。
- 意图说明明确区分 OCR 金额查询与 OCR 进度查询、明确进入提交流程与仅询问提交条件。不得用关键词在服务端替代模型意图判断。
- 评测报告把安全的 `CLARIFY`、模型拒绝等单独视为分类失败或模型失败；`targetReferenceErrors` 仅在模型实际给出错误或未标注的目标引用时计数。未标注的额外单号仍作为安全错误，不能为了提高分数忽略。危险写入目标错误仍单独统计，门槛保持零容忍。

## 验证

先新增会失败的单元测试，分别覆盖模型响应解析、单号核对、评测目标错误口径；再改实现。运行相关单测、类型检查、完整测试和真实模型 `dev-v3`、`holdout-v3`。模型结果可能波动，报告实际指标和门槛，不修改保留集答案。
