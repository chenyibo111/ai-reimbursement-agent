# 财务复核原票预览设计

## 目标

财务人员在处理票据复核案件前，可以在复核中心查看该案件关联的原始票据（JPG、PNG 或 PDF），据此确认识别、更正字段、要求重传或关闭票据。

## 约束

- 仅 `FINANCE_REVIEWER` 与 `ADMIN` 可获取原票预览；员工端没有预览接口。
- MinIO 对象键、访问密钥和内部对象地址不得返回给浏览器。
- 预览 URL 必须是只读、10 分钟有效的 MinIO 预签名 GET URL。
- 预览对象不存在或无法签名时，返回安全的业务错误，不暴露底层存储信息。
- 不引入文件代理或新的持久化表；不改变员工报销工作台。

## 方案

Go API 新增 `GET /api/v1/admin/reviews/{reviewId}/receipt-preview`。它先复用现有财务角色验证，再通过案件的 `receiptId` 查询受信任的票据记录，并在确认对象存在后签发短期只读 URL。

React 复核页新增“查看原票”动作。点击时先在用户手势内打开一个空白标签页，再请求预览 URL；成功后导航新标签页，失败时关闭该标签页并在当前页给出明确错误。这样浏览器不会因异步请求阻止弹窗。

## 接口契约

成功响应：

```json
{
  "url": "https://minio.example/receipts/...签名参数...",
  "expiresAt": "2026-10-23T12:10:00Z"
}
```

案件不存在或不是票据案件返回 `404 REVIEW_CASE_NOT_FOUND`。原票记录或对象不可用返回 `409 RECEIPT_PREVIEW_UNAVAILABLE`，文案为“原票暂不可用，请联系系统管理员后重试。”

## 取舍

没有采用由 Go 服务代理文件流：代理可以获得更严格的即时撤销能力，但会使 API 承担 PDF/图片流量、范围请求和内容处置的复杂性。短时预签名 GET URL 在本地与后续对象存储部署中更简单，且现有系统已经使用同类预签名 URL 完成上传。

## 实施与验证备注

**状态：已完成，并于 2026-10-23 在本地容器环境验证。** 已实现受财务角色保护的预览接口、对象存在性检查、10 分钟只读预签名 URL，以及复核中心的安全新标签页预览动作。Go 全量测试、Web 测试与构建、严格项目审计和差异空白检查均已通过；`reimbursement-api` 与 `reimbursement-web` 容器已重建并成功启动。
