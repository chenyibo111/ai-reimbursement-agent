# Go 政策裁决与 Agent 政策解释一致性

## 目标与边界

Go 报销服务是唯一的提交裁决者。管理员发布的结构化规则由 Go 在预校验、提交确认、最终提交时执行；版本变化使旧确认失效。Agent 的飞书文档问答提供可引用的制度解释，但不宣称未编码的条款已由 Go 自动校验。

## 现状

旧 Next 的 Prisma `PolicyVersion`/`PolicyRule` 与 Go `reimbursement.policy_versions` 是两套不同的数据。Go 只保存版本号，提交校验固定返回 `baseline-v1`。Agent 的政策回答来自飞书文档快照，没有与 Go 可执行规则建立自动等价关系。

## 方案选择

1. 让 Go 读取旧 Prisma 规则：改动少，但重新耦合即将退出的 Next 业务模型。
2. 让模型从文档自动生成校验规则：无法可靠证明语义等价，可能错误阻断或放行。
3. **采用：Go 自有、管理员显式发布的结构化规则；Agent 明示文档解释和系统裁决的边界。** 当前仅支持由 Go 单据字段准确计算的规则，后续增加城市、费用明细等字段时再扩展。

## 行为约束

- Go 发布接口支持版本号、生效日、受控规则列表；拒绝未知类型、字段和错误配置。保留无规则版本的兼容行为，但明确表示没有自动政策约束。
- Go 目前支持整单金额上限、整单费用类别范围、整单类别必填字段。`CATEGORY_ITEM_MAX` 和城市住宿限额因缺少明细/城市字段暂不接受。
- React 的新建和草稿编辑表单提供费用类别、项目编码与同行人，以便员工补齐当前三类规则所需的字段；管理员发布前仍需对照制度原文核对。
- 校验结果带真实生效版本及规则代码、阻断/预警；预警不阻断。没有生效版本时返回显式 `baseline-v1`。
- 提交确认接口把非阻断预警返回给 React，员工一次点击即可完成提交并看到提醒；提交快照中的预警也会在已提交单据详情重新打开时展示。
- 最终提交在数据库事务中锁定当前生效政策，重新校验并检查确认版本；政策变更或阻断规则命中则拒绝，快照记录版本与规则命中结果。
- Agent 政策问答继续引用原文，同时说明这不是提交通过结论，并引导用户查看 Go 当前校验；无法证明文档与结构化规则完全一致时不得称两者相同。

## 非目标

本次不迁移旧 Prisma 规则、不自动把飞书文档转成可执行规则、不实现城市/费用明细级规则、不接入真实审批付款。
