# 管理员配置中心产品方案（建议稿）

> 版本：2026-11-12 · 状态：待评审 · 范围：报销 Web 与飞书 Agent 共用的管理员配置

## 1. 背景与目标

目前管理员可在 `/admin/policies` 发布可执行报销规则，在 `/admin/policy-sources` 管理飞书政策知识来源。票据类型到费用类别、通用事由的映射仍写在代码里；智能补单灰度员工由环境变量指定；OCR 复核阈值、知识检索门槛和部分通知文案也散落在代码中。调整这些内容需要开发或运维介入，且不容易看清某次调整影响了哪些单据。

在管理员区新增独立的 **配置中心**，统一呈现可由业务或运营人员维护的配置。管理员能够编辑草稿、预览影响、发布版本、查看生效状态与操作记录，并在必要时回退。Web、Go 报销服务和飞书 Agent 读取同一份已发布配置；草稿配置不得影响员工业务流程。

**产品原则：** 票据识别建议、员工最终填写值、报销政策校验是三层独立数据。识别建议不能因为政策不允许而被清空；政策知识库问答也不能自动修改可执行规则。

## 2. 用户与权限

| 角色 | 主要工作 | 建议权限 |
| --- | --- | --- |
| 系统管理员 | 管理配置中心、指定配置负责人、处理回退 | 查看全部；创建草稿；发布普通配置；查看审计 |
| 财务配置负责人 | 维护费用类别、表单选项、报销规则、复核策略 | 对负责域创建草稿、预览、发布；高风险变更需复核 |
| AI／知识运营人员 | 维护识别映射、通知模板、知识库与检索参数 | 对负责域创建草稿、预览；按权限发布 |
| 财务复核员 | 了解当前复核标准并处理案件 | 只读相关配置；继续使用现有复核工作台 |
| 员工 | 填写与提交报销单 | 无配置中心权限 |

首期可复用现有 `ADMIN` 角色完成管理，但配置项在数据和界面上仍按领域划分权限，为后续细分角色留接口。任何人不得通过配置界面给自己提升管理员权限；发布与回退必须记录操作者、时间、版本和变更摘要。

## 3. 信息架构

管理员导航新增 **配置中心**，首页显示各领域的当前版本、生效时间、待发布草稿、最近变更和异常提示。下设以下页面：

| 页面 | 管理内容 | 当前来源／目标 |
| --- | --- | --- |
| 业务字典 | 费用类别、项目编码等可选项、名称、别名、排序与停用状态 | 新增；替换报销表单中的自由输入类别，项目编码有主数据时再接入 |
| 智能补单 | 票据类型与类别映射、默认通用事由、未知／其他票据处理、识别配置版本 | 新增；迁移现有固定映射 |
| 功能灰度 | 智能补单等功能的员工名单、部门范围和放量比例 | 新增；迁移现有员工 ID 环境变量名单 |
| 票据复核 | OCR 置信度阈值、复核触发项、提示级别和适用范围 | 新增；保留重复票据安全校验 |
| 消息通知 | Web／飞书通知开关、触发事件、文案模板和预览 | 新增；统一现有通知文案 |
| 知识与 AI | 政策来源、同步计划、检索参数、获准使用的分类模型及提示词版本 | 复用政策来源页并扩展受控参数 |
| 可执行规则 | 金额上限、允许类别、类别必填字段、严重级别、生效日期 | 复用现有政策版本页，纳入配置中心导航 |
| 发布记录 | 版本、差异、影响预览、审批、回退和审计 | 新增通用能力 |

现有 `/admin/policies` 和 `/admin/policy-sources` 在迁移期继续可用；新导航指向同一份数据，不建立第二套政策或知识来源。

## 4. 各领域产品需求

### 4.1 业务字典与表单选项

- 每个费用类别有稳定编码、显示名称、别名、排序、启停状态和可选说明。改名不改变编码；已被单据、映射或政策引用的类别不能直接删除，可停用并继续供历史单据显示。
- 员工在“申请报销信息”中可选择多个最终费用类别。智能补单带出默认选择，员工可增删；每张票据的识别结果保持只读，两者允许不一致。
- 项目编码如接入现有项目主数据，应显示有效项目列表并支持搜索；没有可靠主数据前，保留现有输入方式。同行人继续由员工填写，不在配置中预造人员名单。
- 表单配置首期只覆盖**已有字段**的选项、提示语和展示顺序。新增字段或任意条件表单需先扩展单据数据结构、服务端校验和提交快照，不能仅靠界面配置生成。

### 4.2 智能补单

- 管理员按票据类型配置默认费用类别和通用事由，例如 `TAXI` → “市内交通费”“市内出行打车费”，`OTHER` → “其他”“其他费用”。只能引用已启用类别；发布前检查每个已启用票据类型是否有合法映射。
- 模型仍负责根据 OCR 文字判断票据类型并给出证据；金额继续取 OCR；无法推断的项目编码、同行人及具体业务原因留空。管理员不能通过模板要求模型编造票面外事实。
- 默认类别与 `CATEGORY_ALLOWED` 分离：识别出“其他”就保留“其他”建议；若最终选择违反政策，在报销校验阶段提示或阻断。
- 提供脱敏样票预览：展示模型类型、证据、命中的映射、整单汇总和当前政策校验结果。预览不改真实单据。发布新映射后只作用于后续识别；已有草稿不静默重算，人工修改永不被覆盖。确需重算时由授权人员对指定草稿显式发起并预览差异。

### 4.3 功能灰度

- 支持关闭、指定员工、指定部门、按稳定员工标识百分比放量和全量开启；显示预计影响人数及已启用名单。
- 部门模式只使用可信员工目录同步的部门 ID。当前身份同步尚未传递部门信息；接入并核验部门来源之前，该模式在管理员界面不可发布。
- 智能补单开关对**新建草稿**生效；现有旧模式草稿不自动转换。灰度撤回后已生成的明细和已提交单据保持可读，不删除业务数据。
- 测试与生产环境分别发布，不允许把测试员工名单或测试专用开关自动复制到生产。

### 4.4 票据复核与风险

- 管理 OCR 低置信度进入复核的阈值、复核原因的业务名称与提示文案，以及启用范围。调整前展示近期样本中预计新增／减少的复核数量。
- 重复内容、已提交发票号重复、文件安全检查属于基础风险控制。生产配置中心可展示其状态和统计，但不得提供“一键关闭”入口；现有本地测试豁免不进入生产管理员配置。
- 配置变更只影响之后的识别与复核判断；已建立的案件继续按原案件状态处理。阈值变更不得自动关闭案件或放行待复核票据。

### 4.5 消息通知

- 按“识别完成、需要补充、进入复核、提交成功”等事件配置是否通知、渠道和模板。飞书私聊与 Web 提示分别预览。
- 配置页仅开放已接入真实发送链路的事件和渠道；现有作业通知与事件流通知都须固定模板版本，未接入的事件须先完成发送链路和幂等记录。
- 模板只允许使用白名单变量，如报销单号、票据文件名、识别金额、最终类别和工作台链接；禁止任意表达式、外链或票面全文。预览应覆盖缺失金额、分类失败、多张票据和长文案。
- 已排队的通知按创建时记录的模板版本发送，避免发布新文案后同一事件前后内容不一致。发送失败沿用现有重试与审计机制。

### 4.6 知识与 AI 运行参数

- 保留现有飞书 Docx／Wiki 来源的添加、启停、手动同步；新增同步计划、最近成功快照、失败告警状态。同步失败继续使用上次成功内容。
- 检索条数、相关性门槛等作为**高级参数**，仅授权运营人员可调整；发布前用固定政策问答样本展示“有引用／无引用／误引用”变化。检索门槛不影响可执行报销规则。
- 管理员可选择平台预先批准的分类模型与提示词版本、查看分类成功率和费用；模型服务地址、API Key 等凭据由运维密钥系统维护，配置中心只显示脱敏标识和连接状态。

### 4.7 可执行报销规则

- 现有规则发布能力纳入配置中心入口，继续由财务负责人发布新版本，保留生效日期、阻断／提示级别和提交快照。
- 规则编辑器引用业务字典的稳定类别编码，展示类别名称，发布前校验停用类别、重复规则和互相冲突的条件。知识库文档更新仍不会自动发布规则。
- 未来新增城市住宿档位、单笔限额等规则时，先确认单据已有可靠的城市、明细等事实字段和复核方式，再开放对应规则类型。

## 5. 通用配置生命周期

`创建草稿 → 编辑 → 校验 → 影响预览 → 提交发布 → 生效 → 监控 → 必要时回退`

1. **草稿：** 与当前生效版本隔离；多人编辑采用版本冲突提示。页面展示字段级差异及关联配置，例如类别改名会影响哪些映射和规则。
2. **发布校验：** 检查编码唯一、引用有效、模板变量合法、范围冲突、参数上下限和跨领域依赖。高风险项，如复核阈值、检索门槛、模型版本和阻断规则，要求指定负责人复核。
3. **发布：** 生成不可变版本，记录环境、生效时间、操作者、复核者和变更说明。服务只读取完整的已发布版本；读取失败时保持最后一个可用版本并告警，不落入半发布状态。
4. **回退：** 将生效指针切回经验证的旧版本并记录原因；不修改旧版本内容、不回写已提交单据。支持先在测试环境验证，再按灰度范围发布到生产。
5. **审计：** 记录创建、修改、预览、发布、回退、读取失败等事件。页面可按配置域、人员、时间和单据使用的版本查询。

配置采用不可变快照和受控发布，以便稳定读取和回退；这是成熟配置服务常见的安全做法。参考：[Azure App Configuration 快照](https://learn.microsoft.com/en-us/azure/azure-app-configuration/concept-snapshots)、[AWS AppConfig 发布与回退](https://docs.aws.amazon.com/appconfig/latest/userguide/appconfig-deploying-reverting.html)。密钥与普通配置分离，参考：[Azure App Configuration 安全指南](https://learn.microsoft.com/en-us/azure/azure-app-configuration/secure-azure-app-configuration)。

## 6. 生效范围与历史数据

| 场景 | 预期行为 |
| --- | --- |
| 发布新的类别映射或事由模板 | 后续完成 OCR 的票据使用新版本；已识别票据和手工修改的整单字段不自动改变 |
| 新增或停用费用类别 | 新草稿使用新选项；旧单据保留原类别编码与当时名称快照，可继续查看 |
| 发布新的可执行规则 | 按规则生效日期用于预校验与提交；已提交单据的政策快照不重算 |
| 调整 OCR 复核阈值 | 只影响后续识别；已存在的复核案件继续处理 |
| 调整灰度名单 | 新建草稿按新配置判断；存量草稿模式不静默切换 |
| 调整通知或检索参数 | 后续通知／问答使用新版本；历史消息和引用保留原样 |

每条识别结果、最终提交快照和通知应能关联所使用的配置版本，以便事后解释；配置回退不能删除原始结果或审计记录。

## 7. 分阶段交付建议

| 阶段 | 范围 | 完成标志 |
| --- | --- | --- |
| 第一阶段：配置底座与业务字典 | 配置中心导航、权限、草稿／版本／审计／发布／回退；费用类别、票据类型映射、通用事由、现有政策页入口 | 管理员无需改代码即可调整分类默认值；Web 与飞书读取同一发布版本；政策校验仍独立 |
| 第二阶段：业务运营配置 | 表单选项、智能补单灰度、通知模板、复核阈值；迁移现有硬编码和员工名单 | 可预览影响并灰度发布；测试与生产配置隔离；历史草稿和案件不被重写 |
| 第三阶段：知识与 AI 高级配置 | 自动同步计划、检索参数、获准模型／提示词版本、离线样本评估与指标 | 配置发布有样本评估结果；知识问答与可执行规则继续独立；错误版本可回退 |

现有政策来源和政策规则页面在阶段一只做导航整合；功能迁移与页面统一可随对应阶段完成，不影响已经发布的政策版本。

## 8. 验收场景

1. 管理员将 `TAXI` 默认类别调整为“交通费”并发布；新打车票带出“交通费”，旧已提交单据仍显示原值和原配置版本。
2. “其他”票据的识别结果正常显示“其他”；若当前 `CATEGORY_ALLOWED` 不允许“其他”，提交校验明确提示，识别类别不被清空。
3. 一张打车票加一张餐饮票使整单默认选中两个类别；员工修改最终类别后，后续新增票据不覆盖人工选择。
4. 管理员缩小智能补单灰度范围；未进入范围的员工新建旧模式草稿，已有明细草稿仍可读、可提交。
5. 发布更高 OCR 复核阈值后，新票据按新阈值分流，已领取案件和已提交单据不变化。
6. 通知模板包含非法变量、映射引用停用类别、政策规则引用不存在类别时，发布被阻止并给出具体原因。
7. 知识库同步失败仍能使用上次成功快照；降低检索门槛不会自动改变报销规则或提交结果。
8. 回退任一配置版本后，新请求读取回退版本，历史单据、历史通知与审计仍能追溯原版本。

## 9. 成功指标与待确认项

建议观察：分类建议可用率、人工更正率、缺失类别率、复核量与误判率、政策阻断原因、知识问答有引用率／误引用率、通知失败率、配置发布失败及回退次数。指标按配置版本和灰度范围拆分，以便判断某次调整的实际效果。

落地前需确认三项业务决策：

1. 配置是当前企业统一一套，还是未来需要按法人／部门维护多套？本方案首期按**企业统一配置**设计，灰度可按员工和部门划分。
2. 高风险配置由谁复核发布？本方案建议财务负责人复核报销规则与复核阈值，AI／知识运营负责人复核模型与检索参数。
3. 项目编码的权威来源是什么？在接入主数据前，不将管理员手工录入的项目列表视为有效项目证明。

本文件为产品需求方案，不包含数据库表、API 契约、工期或实施承诺；这些在范围确认后另行形成技术方案和分阶段任务。
